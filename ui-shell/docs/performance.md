# 真实游戏界面的构建与性能检查

检查日期：2026-10-03，Asia/Singapore。本机 macOS、Node.js 24、Playwright Chromium，访问 Vite 本地生产预览，没有 CPU/网络限速。原始报告和截图在忽略的 `test-results/game-browser-report.json` 与 `game-*.png`；本页是当前真实游戏入口的检查，早期四文明演示记录另见 [`performance-demo.md`](performance-demo.md)。

## 验证

- 生产构建通过；原八组规则/经济/人口/双语/地图/工作区/生成世界检查通过。
- 新 host 一致性检查通过：三个种子各连续 30 次行动，与原引擎状态、RNG 对照；禁用命令不推进年份，旧固定地图迁移、导入失败保护、战损、雾区过滤、分裂、灾变继承、重启、结局和日志清理均覆盖。
- 真实浏览器16/16检查通过：新局与地图选址、21 决议、引文/出处独立分行、指标和事件、快捷键、历史只读、战略与部署、军事迷雾、导入导出重载、固定/显式/随机种子、危机/重启/独立结局页、自动推演、空闲绘制、拖动缓存及四种布局。结局页覆盖刷新恢复、返回后重新进入、分页观测与省份记录、取消/实际建立新世界、导出并重新导入终局。
- 立体 / 平面额外10项浏览器检查通过：切换时相机/相对缩放/正式存档不变，两视角省份和军队命中，鼠标缩放锚点误差至多1px，短距离平移缓存复用，视角刷新恢复。正逆投影、四角范围和视觉随机数隔离单测通过。
- 本次浏览器无未捕获异常或 HTTP 失败；四种视口横向溢出均为 0。每个上下文隔离，测试不会改日常浏览器的有效存档。

## 当前规模

真实生成世界为 64 省、10 战略区域、5 势力。默认一张地图 Canvas，一张小指标 Canvas；一个脱离 DOM 的地图缓存。默认只加载当前执政官肖像，全部图片 lazy / async。约360个 DOM 节点含64个原生省份选项和25个小 SVG 图标，没有省份 SVG 或地图标记 React 组件。立体山体与海岸厚度使用预编译 Path2D，进入原底图缓存；未增加画布或持续渲染循环。

| 视口              |  地图像素 | 地图缓存像素 | 全部 Canvas 原始缓冲估算 | DOM |
| ----------------- | --------: | -----------: | -----------------------: | --: |
| 1440×900 / DPR 1  |   486,772 |      756,700 |                  5.11 MB | 362 |
| 3840×2160 / DPR 2 | 2,398,767 |    2,399,724 |                 20.46 MB | 360 |
| 1024×768 / DPR 1  |   228,944 |      373,968 |                  2.50 MB | 360 |
| 390×844 / DPR 1   |   134,160 |      244,496 |                  1.58 MB | 360 |

每张主要地图 surface 最多240万像素；4K时主动降低内部密度。4K地图与缓存原始 RGBA 约19.19MB，加上指标画布约20.46MB。这里不是页面内存上限，未计入路径、解码图片、GPU副本、快照与浏览器开销。Chromium `performance.memory` 只返回粗粒度约10MB堆读数，不作为精确内存结论。

## 绘制和加载

- 空闲1秒新增地图绘制 **0次**，无常驻绘制循环。
- 桌面60步短距离拖动，合并为58次绘制，只重建底图1次；绘制提交P50 **0.5ms**，P95 **0.9ms**，最大 **12.8ms**。本次多个隔离浏览器并行检查，这些只是本机提交耗时。
- 地形缓存采用有限外扩区域（按尺寸决定，最大128 CSS px），越界或缩放时重建。选择、阵营与年份变化只重绘动态层。
- 冷上下文首轮加载/建国子资源传输约 **199KB**，排除HTML。默认入口没有请求历史展示的 JS/CSS；当前头像约18KB。
- 结局页 JS/CSS 仅终局打开时请求，合计约9.75KB gzip；进入后卸载游戏地图。三日背景用 CSS 绘制，归档观测/省份每页至多16条，文明每页至多12代。
- 四张执政官肖像从1,465,500降至73,900 bytes，约减少95%；默认不全量加载。未使用的双语catalog从React加载链移除，传统双语入口保留。
- 本次冷启动与四种视口未记录到超过50ms的长任务；4K首次立体底图构建约30.8ms。先前较长桌面流程曾记录过约65ms长任务。世界生成与原引擎初始化仍在主线程，不能用缓存后的低耗时宣称所有操作都低于一帧预算。

`drawMs` 来自 Canvas 绘制入口的 `performance.now()`，度量提交绘制指令，不包括全部异步GPU栅格化，不能换算真实FPS。输入按步等待帧，仅是本机基础检查，非Lighthouse、持续压力测试或弱设备保证。

## 主要风险与后续触发条件

1. 缩放、跨出底图缓存、窗口改变和新世界会重建地形；4K遵守预算会降低文字/边缘清晰度。
2. 64省范围内线性筛选和复制快照足够。若扩展数千省/军队，再加入空间索引、缩放分级，测量结算耗时后决定是否需要Worker。
3. 时间图保留最近80次观测，编年史最多80条、文明档案最多12代，沿用原引擎上限；界面每页只挂载20条记录。这不是可任意回放的完整历史快照。
4. Safari/Firefox、低功耗设备、触屏手势和超长自动模拟尚未专项验收。390px只验证了可滚动布局与无横向溢出，产品仍优先桌面。
5. 随机地图始终由存档版本和种子决定，新生成器版本必须保留旧地图迁移逻辑。不同源的存档用JSON导入导出，不会自动共享。
