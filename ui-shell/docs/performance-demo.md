# 构建、交互与性能检查

检查日期：2026-10-01（Asia/Shanghai）。环境为本机 macOS、Node.js 24、Playwright Chromium 145，访问 Vite 的本地生产预览。没有 CPU 或网络限速。这是基础性能检查，不是 Lighthouse、跨浏览器认证或真实设备 FPS 基准。

## 检查范围

`npm run build` 生成静态 `dist/`。`npm test` 验证四文明、16 事件、81 个年份快照、边界、确定性、不可变性及坐标。原仓库八组游戏回归检查全部通过。

`npm run test:browser` 的 13 组检查覆盖：首屏与图片、四文明切换、详情标签与键盘导航、时间范围与播放终止、事件定位、具体城市定位、搜索与空状态、收藏及刷新恢复、设置/贸易、地图点击/缩放/裁剪、60 步拖拽与静止重绘、响应布局、浏览器异常与 HTTP 失败。

产物位于 `test-results/`：完整 JSON、1440×900 桌面截图、3840×2160/DPR 2 截图、1024×768 紧凑桌面截图、390×844 窄屏截图。浏览器新上下文相互隔离；收藏测试不影响日常浏览器存储。

## 如何理解测量

- 绘制耗时来自地图绘制入口到结束的 `performance.now()`，包括重建底图时提交的 Canvas 指令。浏览器可能异步完成 GPU 栅格化，因此它不能换算为实际 FPS。
- 拖拽为 60 次输入，每次等两个动画帧后采样；用于复现绘制成本，不模拟持续高速输入或强压场景。
- 空闲 1.1 秒内绘制次数必须保持不变，验证没有常驻绘制循环。
- 资源流量统计包含 JS、CSS、地图和图片子资源，未包含 HTML 文档本身。Vite 预览可能压缩传输，因此与构建文件大小不同。
- `performance.memory` 在本次浏览器返回整齐的分桶数字（10,000,000 bytes），只保留原始读数，不视为精确页面内存。它不包含全部 GPU、浏览器或图片解码内存。
- 画布缓冲内存估算为 `width × height × 4 × 2`，仅代表可见面与底图缓存的原始 RGBA；纹理缓存、路径、解码图片和浏览器自身开销另计。

## 仍需关注

1. 当前只有 16 个标记和四个疆域，裁剪仍线性扫描。数千实体需要空间索引、缩放分级和更多场景测试。
2. 4K 为遵守像素预算会降低地图内部像素密度，清晰度与内存之间有明确取舍。地图文本属于 Canvas，也会受影响。
3. 四张图片固定为 768×384，总计 309,100 bytes。新增大量素材时应延续按需挂载、合适分辨率和预算，不能全量预加载。
4. 年份变化目前是四条记录的合成快照。接入真实模拟、长历史、远程数据后需要重新测量快照计算和传输成本；不要把模拟逻辑放进绘制函数。
5. 桌面为主；窄屏只提供可滚动的布局退化。移动触屏、Safari/Firefox、低功耗设备尚未完成专项验证。
6. 原 sample 图片没有包含在可读取的旧对话里，本次以明确的文字方向和原创素材制作；没有完成原图逐像素验收。

最终数值及优化对比见下方结果，原始报告为 `test-results/browser-report.json`。

## 最终结果

13/13 组浏览器检查通过，无未捕获异常，无 HTTP 失败。所有检查窗口均无横向溢出。首屏只有一张已挂载的埃及插画，具有 lazy / async 属性，未下载其他三个文明的图片。

| 视口 | Canvas 像素 | 初次测得绘制耗时 | FCP / LCP（本地） |
| --- | ---: | ---: | ---: |
| 1440×900，DPR 1 | 673,552 | 12.9 ms | 56 / 88 ms |
| 3840×2160，DPR 2 | 2,398,800 | 38.4 ms | 68 / 128 ms |
| 1024×768，DPR 1 | 392,660 | 9.5 ms | 52 / 80 ms |
| 390×844，DPR 1 | 189,840 | 7.8 ms | 44 / 56 ms |

- 桌面 60 次拖动绘制：P50 **17.3 ms**，P95 **17.9 ms**，最大 **18.1 ms**；空闲 1.1 秒新增绘制 **0 次**。
- 优化前同一检查的 P50 / P95 为 18.9 / 19.5 ms。将山脉、水纹、河流、网格等预编译为 7 组 Path2D 并缓存 CanvasPattern 后有所降低；这是本机单次对比，不是统计显著性结论。
- 四种视口均为 **291 个 DOM 节点、28 个小型 SVG 图标、1 个可见 Canvas**。重置时 16/16 标记可见；放大后标记数量减少，验证视口裁剪。
- 首屏子资源传输 **181,579 bytes**（约 177 KiB，含当前插画，排除 HTML）；四张插画总文件大小 **309,100 bytes**。
- 4K 的两块主要 Canvas 缓冲估算为 **19,190,400 bytes**（约 18.3 MiB）。表中四种首次加载均未记录到超过 50 ms 的 long task。

17.9 ms 的绘制 P95 已接近且略高于 60 Hz 的 16.7 ms 单帧预算，因此不承诺持续拖动时稳定 60 FPS。若下一阶段要求高刷新率，优先考虑缩放级别分块缓存/平移复用，再测低功耗设备；无需仅为这个原型引入 WebGL 引擎。
